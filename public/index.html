Could Redbelly connect to Quant Overledger?

A feasibility report on interoperability between Redbelly Network and Quant's Overledger. What Overledger is, whether Redbelly can reach it, what that would take, and where compliance could break.

Feasibility research only. Redbelly and Quant have no announced partnership or talksS1, and nothing in this report suggests otherwise. Redbelly has not published an official position on bridgingS1, so any question that no public source answers is marked Unknown.

00Short answer

Key findings

01Analysis

Could Overledger's Gateway reach Redbelly today, for reading data and sending signed transactions?

Possibly

Possibly, but unconfirmed. Redbelly is EVM compatible and its RPC fits Overledger's self-serve tests, but Overledger describes self-serve as for public permissionless networks, and writing to Redbelly needs a credential. Nobody has shown it working.S2S3S4S5

02Analysis

Can Redbelly join the Fusion Rollup, Overledger's shared layer for deposits, unified token balances and cross-chain messages?

Not yet

Not possible yet, as far as public sources show. Redbelly is not among the networks documented at testnet launch, and the docs describe no self-serve way to add one.S6S7

03Analysis

Would Receptor credentials and Tokeniser rules travel with an asset to another chain?

No

No, not by themselves. Redbelly's access credential and Proof by Query checks run on Redbelly, and Tokeniser enforces its rules at the point of transfer. A copy on another chain follows only that chain's own rules.S5S8S9

04Confirmed

Is there any agreement between Redbelly and Quant?

None

None has been announced.S1

01Context

Why this question comes up now

Confirmed

On 24 September 2026 The Clearing House said it selected Quant to power its On-Chain Money Initiative, a payments network for clearing and settling tokenised deposits between financial institutionsS10. Quant's technology is to provide the network's interoperability, orchestration and transaction management layerS10, with connectivity to existing payment systems such as RTP and CHIPSS10. Quant's own release says The Clearing House will use Quant's technology to bring on-chain capabilities to its tokenised deposit networkS11.

Confirmed

The network is expected to be available to participating institutions in the first half of 2027, and details on participation and use cases are still to be announcedS10.

Unknown

Neither announcement names any blockchain the network will use or connect to, and neither mentions Redbelly. No public source we found says whether it will connect to Redbelly or to any other specific chainS10.

02Overledger

What Overledger is

Confirmed

Overledger is Quant's platform for building applications that span more than one blockchainS12. It has three foundations: a Gateway that authenticates clients and routes requestsS13; Connectors that put each chain's own RPC protocol behind one common interfaceS13; and the Fusion Rollup, a shared layer that anchors to several chains at once and supports deposits, withdrawals and cross-chain messages between themS13.

Analysis

In plain terms, the Gateway and Connectors are a switchboard: one login and one interface to talk to many chainsS13. The Fusion Rollup is different. It is a separate EVM-compatible layer: tokens deposited from the chains connected to it appear as balances on the rollup and can be withdrawn back to those chainsS13. The rollup connects to only a subset of the networks the Gateway reachesS13, so a chain can be reachable through the switchboard without being connected to the Fusion Rollup.

Confirmed

Multi-step workflows such as signing or deploying a contract run as Flow AppsS12. Signing can be done with the user's own keysS14, and the client never sees private key materialS14.

03Overledger

How chains connect to Overledger today

Confirmed

There are two routes. The self-serve route covers six chain families, including EVM, where an account can register a node and use the network without talking to Quant's account teamS3. The self-serve EVM family is described as covering every EVM-compatible chainS3, but self-serve Connectors are for public, permissionless chain familiesS3, and permissioned EVM networks such as permissioned Hyperledger Besu are on the engagement routeS3. The managed engagement route is for private or consortium networks, and for chain families Quant does not support yetS13.

Confirmed

A chain family qualifies for self-serve when its nodes offer an interface over HTTPS, need nothing beyond an API key, and it does not matter which node a client usesS3. Networks where node identity matters, such as permissioned consortium chains and operator-gated public chains, are not self-serve todayS3.

Confirmed

A chain that is not listed yet, but belongs to one of the six self-serve families, is added with the same registration call that adds a nodeS3. The first registration creates the network, and it then becomes available to other Overledger usersS3.

Confirmed

Each node is registered as public or private. A public node must come from an approved provider and joins the shared pool for that networkS3, while a private node can be at any address but is scoped to the account that added itS3. The approved providers are Alchemy, Infura, QuickNode, Chainstack, GetBlock, Blockdaemon and AnkrS3, and a public node URL must carry the provider's API keyS3. A private node can be any reachable HTTPS addressS3. Every node must pass a health check before it is usedS3.

Confirmed

When a brand-new chain family is needed, the documented effort is about 2 days for a health and chain identity checker, plus about 1 day for each app that needs to use itS3.

04Redbelly

The Redbelly facts that matter here

Confirmed

Redbelly is a layer 1 blockchain built for real world asset tokenisationS15. It is compatible with the Ethereum Virtual Machine and runs smart contracts written for itS2. Mainnet is chain ID 151 with a public RPC addressS16, and Redbelly lists Ankr as a third-party public RPC provider for mainnetS16. Testnet is chain ID 153S16.

Tested

On 15 October 2026 the official mainnet RPC and the Ankr RPC both answered with chain ID 151 (0x97)S4, and the official mainnet RPC returned the latest blockS4. The method net_version, which gives a network ID to wallets and tools that predate eth_chainIdS6, returned "the method net_version does not exist/is not available"S4.

Confirmed

Writing to Redbelly is gated by identity. Every user must claim an access credential from an accredited issuer before their account can write to the networkS5, and all participants must prove who they are before gaining accessS17. Accredited issuers are listed in an on-chain registryS18. Businesses can also be verified as incorporated entitiesS17S19, and even node operators need network access for their accountsS20.

Confirmed

Receptor is Redbelly's identity and verifiable credential protocolS24, built on the W3C verifiable credential data modelS24. It supports two methodsS25. Proof by Query uses a zero knowledge verifier smart contractS8 and publishes identity state to the chainS8. Selective Disclosure uses BBS+ signaturesS26, reveals chosen details to a verifier, and can only be used off-chainS26. The documented issuer identifiers for Redbelly environments take the form did:receptor:redbellyS27, and apps can use eligibility checks to control who may call their contract functionsS28.

Confirmed

Tokeniser runs on RedbellyS9 and enforces eligibility, identity and target market rules at the point of transfer, every timeS9. Before any trade proceeds, identity, eligibility and limits are checkedS29; transfers are recorded on the register in real timeS30; and pledged units stay locked until a loan is repaidS31. Redbelly settles a transaction in a single roundS9.

Confirmed

Redbelly already has token bridges. Its developer portal lists three routes: Celer cBridgeS21, LayerZero with StargateS22 and Lucid LabsS23. Celer uses a pegged bridge methodS32, and its RBNT route goes out from Redbelly but not backS21. Redbelly announced Wrapped RBNT on Ethereum with the contract 0xb45f...bf13S33, which the portal lists under Lucid LabsS23. The portal lists a different Ethereum contract for the Celer routeS21.

Confirmed

Community research for TASK-08 found LayerZero live on Redbelly mainnetS34. A second TASK-08 entry found that, when it was written, no major interoperability protocol had deployed core messaging infrastructure to Redbelly testnetS35, and the selected entry built a lock-and-mint testnet bridgeS34. The TASK-16 playbook says the bridges it calls official, Reddex and Lucid, then supported only bridging USDC and USDT from BNB ChainS36.

05The answer

Can Redbelly connect now, and what is missing?

A connection can mean three different things. Each has a different answer.

Analysis

Level 1: reaching Redbelly through the Overledger Gateway. Possibly, unconfirmed.

Redbelly is EVM compatibleS2, and Overledger's self-serve EVM family is described as covering EVM-compatible chainsS3. An unlisted network in a self-serve family can be added by the first node registrationS3. At the RPC level Redbelly appears to fit the self-serve testsS3: its RPC works over HTTPS and answered without a key, two different endpoints returned the same chainS4, and its write rule is attached to accountsS5, not to the node a client uses. Ankr, an approved providerS3, runs a Redbelly mainnet endpointS16, and the official RPC could be added as a private nodeS3.

Analysis

If it works, this level would give an institution one interface to read Redbelly data and send transactions it has signed itself. After its own access checks, the Gateway forwards the payload to a Redbelly node and passes back the native response unchangedS3, so Redbelly's own rules still apply. A transaction sent this way only succeeds if the sending account has Redbelly write accessS5.

Unknown

Four points are open. First, how Overledger would classify Redbelly. Self-serve is written for public, permissionless networksS3, Overledger's own glossary calls a network where anyone can read but only allowlisted parties can write "public permissioned"S13, and permissioned EVM networks are on the engagement routeS3. Writing to Redbelly needs an access credentialS5, so Redbelly could be treated as an engagement network; the docs do not say. Second, the docs say only that the health check uses the chain's standard validationS3 and that a checker does a chain identifier lookupS3, not which call the EVM check uses. If it relies on net_version, Redbelly's answerS4 could fail it. Third, a public node URL must carry a provider API keyS3, and we did not confirm that Ankr's keyed service covers Redbelly. Fourth, Overledger's live network listS3 and the Fusion Rollup's listS38 both answered "Missing authorization header" without an API keyS7, so we could not see whether Redbelly is already listed.

Analysis

Level 2: Overledger Flow Apps on Redbelly. Unknown.

Flow Apps are multi-step workflows run through the GatewayS12, and customers and partners can also host their ownS13. The catalogue is not publishedS14 and every shipped app is built by QuantS14, so whether a given app accepts a self-serve EVM network such as Redbelly cannot be checked from public sources. The docs give an effort of about a day per app only for adding a brand-new chain familyS3; they give no figure for a new network inside a family Overledger already supports.

Confirmed

Level 3: joining the Fusion Rollup.

The networks documented as connected at testnet launch are Ethereum Sepolia, Polygon Amoy and Quant's permissioned Besu testnetS6. Each connected chain carries the rollup's bridge and dispute contractsS6 and receives the rollup's state rootsS6. Token entries on the bridge are controlled by Quant's governance signersS37.

Analysis

Not possible yet, as far as public sources show.

Redbelly is not in the documented list, the live list could not be read without an API keyS7, and the documentation we read describes no self-serve way to add a chain to the Fusion Rollup. Joining would also have a Redbelly side: every account that writes needs an access credentialS5, so the accounts that deploy the rollup's contracts and post its state roots would each need Redbelly network access. No such work has been announcedS1.

06The answer

The technical work a connection would need

Written for a non engineer. Steps marked Level 1 are small. Steps marked Level 3 depend on Quant, because Redbelly is not among the documented Fusion Rollup networksS6 and bridge tokens are added by Quant's governanceS37; the accounts involved would also need Redbelly accessS5. No such work has been announcedS1.

Analysis
  1. 1Level 1, step 1Someone with an Overledger account registers a Redbelly node: the official RPC as a private nodeS3 or, if an approved provider's keyed service covers Redbelly (not confirmed), that provider's endpoint as a public nodeS3. The first registration also adds the networkS3. This is one form or one API callS3.
  2. 2Level 1, step 2The node has to pass Overledger's health checkS3. If the check fails, the node is not added, and the docs do not say what would happen next. For scale, a checker for a brand-new chain family is documented at about 2 daysS3.
  3. 3Level 1, step 3Every address an institution sends from needs Redbelly write access, which its user enables after claiming an access credential from an accredited issuerS5. The organisation can also be verified as a businessS19. They can sign with their own keysS14.
  4. 1Level 3, step 1The rollup's standard bridge and dispute contracts are deployed on RedbellyS6, from accounts that hold Redbelly accessS5.
  5. 2Level 3, step 2The rollup's services start posting rollup state roots to Redbelly for settlementS6.
  6. 3Level 3, step 3Each token that should move is added to the bridge token list by Quant's governanceS37.
  7. 4Level 3, step 4Issuers decide whether their asset contracts may hold or release tokens to the bridge contract, because Tokeniser checks eligibility on every transferS9.
  8. 5Level 3, step 5Someone would have to keep Overledger's own allowlistsS37 in step with Receptor credentialsS5, because neither system's documentation describes a link to the other.
Analysis

Registering a node is a technical action any Overledger account can takeS3. It would not by itself mean any agreement between Redbelly and Quant.

07Institutions

What a connection could offer institutions

Analysis
  • One interface. An institution that already reaches other chains through OverledgerS12 could read Redbelly and send its own signed transactions through the same Gateway and firewall checksS13, without managing its own Redbelly RPC providers or node failoverS12, once a Redbelly node is registeredS3.
  • Rules stay on Redbelly. At Level 1 the Gateway passes each payload to a Redbelly node and passes back the native response unchangedS3, so Redbelly's access credential still applies to every sending accountS5, and Tokeniser's eligibility checks still apply to every transfer of a Tokeniser assetS9.
  • Key control. Institutions can keep and use their own keys in Overledger's modelS14.
  • Unified balances, only at Level 3. The Fusion Rollup can merge copies of the same token from several chains into one balanceS6. Redbelly is not among the documented connected networksS6, so as far as public sources show this is not available to Redbelly.
  • No known route to tokenised deposit networks yet. The Clearing House network will use Quant's technology for its interoperability layerS10, but the announcements do not say which chains it will use. Whether it will ever reach Redbelly, or any public chain, is unknownS10.
Analysis

Limits to weigh. Redbelly's developer portal already lists bridge routes through Celer, LayerZero and Lucid LabsS21S22S23, and Tokeniser points to EVM compatibility as its link to other networksS9. Overledger would add an institutional access layer rather than a first route out. Level 3 would also put Quant's governance signers in the path, since they control which tokens may cross the Fusion bridgeS37, and withdrawals from the rollup wait for a dispute windowS6, unlike Redbelly's single round settlementS9.

08Compliance

Receptor credentials and Tokeniser assets across chains

Analysis

How Receptor credentials would behave

A Receptor credential is a W3C verifiable credential held by the userS24. Its two methods travel differently. A Selective Disclosure proof is checked off-chainS26, so in principle any verifier could check it, including an externally hosted Overledger Flow AppS13; we found no such app, and every shipped app is built by QuantS14. A Proof by Query check runs in a verifier contract against identity state published on RedbellyS8, so another chain cannot run the same check unless that setup is rebuilt there. The access credential that unlocks write access applies to Redbelly onlyS5.

Analysis

How Tokeniser assets would behave

Tokeniser enforces a Tokeniser asset's rules on Redbelly at every transferS9S29. A lock-and-mint bridge, the pattern of the TASK-08 testnet bridgeS34, locks the asset on one chain and issues a copy on the other. The copy obeys only the rules of the contracts and policies on the other chain. Overledger's firewall decides access from its own list of users and their addressesS37, not from Receptor credentials.

Analysis

Where compliance could break

  1. A copy on another chain without eligibility checks could be passed to someone who never proved eligibility on RedbellyS9.
  2. Two lists of who is allowed: Receptor credentials on RedbellyS5 and Overledger's allowlistsS37. If they drift apart, one system allows what the other refuses.
  3. A revoked credential on RedbellyS5 does not reach a copy held elsewhere unless someone updates the other listS37.
  4. Merged balancesS6 could mix a restricted asset with an unrestricted copy of the same asset.
  5. The list of tokens that may cross the Fusion bridge is set by Quant's governanceS37, not by the issuer.
  6. The register is kept on Redbelly in real timeS30. Units held on another chain, or locked in a bridgeS31, need clear treatment in that register.
  7. Settlement timing changes: rollup withdrawals wait for a dispute windowS6, while Redbelly is final in one roundS9.
Analysis

The lowest risk pattern is for regulated assets to stay on Redbelly and for Overledger to carry only instructions and data at Level 1, so that every transfer still meets Redbelly's checksS3S5S9.

A few paragraphs

Could Redbelly connect to Quant's Overledger? We looked only at public documents. Redbelly and Quant have not announced any partnership or talks, and this research does not suggest any.

Overledger is Quant's platform for reaching many blockchains through one interface. Its self-serve route covers EVM chains, and Redbelly is EVM compatible, so a basic connection, reading Redbelly and sending transactions the sender has signed, looks possible. It is untested, and Overledger describes self-serve as for public permissionless networks, while writing to Redbelly needs a credential. Every Redbelly rule would still apply.

Overledger's Fusion Rollup, its shared layer for moving tokens between chains, does not list Redbelly among its connected networks, and the docs describe no self-serve way to add a chain. As far as public sources show, that part is not possible today.

Receptor credentials and Tokeniser's eligibility rules are enforced on Redbelly. They do not travel with a token to another chain. Keeping regulated assets on Redbelly avoids that gap.

Open questions: whether Overledger would treat Redbelly as self-serve, whether Redbelly passes its network check, which chains The Clearing House network will reach, and Redbelly's own position on bridging. The full report and every source are linked below.
