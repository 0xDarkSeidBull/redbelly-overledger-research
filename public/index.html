Could Redbelly connect to Quant Overledger?

A feasibility report on interoperability between Redbelly Network and Quant's Overledger

Feasibility research only. Redbelly and Quant have no announced partnership or talks[1], and nothing in this report suggests otherwise. Redbelly has not published an official position on bridging[1], so anything not found in a public source is marked Unknown.

1. Why this question comes up now

Confirmed

On 24 September 2026 The Clearing House said it selected Quant to power its On-Chain Money Initiative, a payments network for clearing and settling tokenised deposits between financial institutions[9]. Quant's technology is to provide the network's interoperability, orchestration and transaction management layer[9], with connectivity to existing payment systems such as RTP and CHIPS[9]. Quant's own release says the same[10].

Confirmed

The network is expected to be available to participating institutions in the first half of 2027, and details on participation and use cases are still to be announced[9].

Unknown

Neither announcement says which blockchains the network will reach. Whether it will connect to any public chain, Redbelly included, is not public[9].

2. What Overledger is

Confirmed

Overledger is Quant's platform for building applications that span more than one blockchain[11]. It has three foundations: a Gateway that authenticates clients and routes requests[12]; Connectors that hide the differences between each chain's interface behind one common interface[12]; and the Fusion Rollup, a shared layer that anchors to several chains at once and supports deposits, withdrawals and cross-chain messages between them[12].

Analysis

In plain terms, the Gateway and Connectors are a switchboard: one login and one interface to talk to many chains. The Fusion Rollup is different. It is a separate chain run by Quant's system that holds tokens deposited from the chains connected to it. A chain can be reachable through the switchboard without being connected to the Fusion Rollup[12].

Confirmed

Multi-step workflows such as signing or deploying a contract run as Flow Apps[12]. Signing can be done with the user's own keys[13], and the client never sees private key material[13].

3. How chains connect to Overledger today

Confirmed

There are two routes. The self-serve route covers six chain families, including EVM, where an account can register a node and use the network without talking to Quant's account team[2]. The EVM family covers every EVM compatible chain[2]. The managed engagement route is for private or consortium networks, and for chain families Quant does not support yet[12].

Confirmed

A chain family qualifies for self-serve when its nodes offer an interface over HTTPS, need nothing beyond an API key, and it does not matter which node a client uses[2]. Networks where node identity matters, such as permissioned consortium chains and operator-gated public chains, are not self-serve today[2].

Confirmed

A chain that is not listed yet, but belongs to a supported family, is added with the same registration call that adds a node. The first registration creates the network, and it then becomes available to other Overledger users[2].

Confirmed

Each node is registered as public or private. A public node is shared with all users and must come from an approved provider, and a private node can be any address but only its owner can use it[2]. The approved providers are Alchemy, Infura, QuickNode, Chainstack, GetBlock, Blockdaemon and Ankr[2], and a public node URL must carry the provider's API key[2]. A private node can be any reachable HTTPS address[2]. Every node must pass a health check before it is used[2].

Confirmed

When a brand-new chain family is needed, the documented effort is about 2 days for a health and chain identity checker, plus about 1 day for each app that needs to use it[2].

4. The Redbelly facts that matter here

Confirmed

Redbelly is a layer 1 blockchain built for real world asset tokenisation[14]. It is compatible with the Ethereum Virtual Machine and runs smart contracts written for it[3]. Mainnet is chain ID 151 with a public RPC address[15], and Redbelly lists Ankr as a third-party public RPC provider for mainnet[15]. Testnet is chain ID 153[15].

Tested

On 15 October 2026 the official mainnet RPC and the Ankr RPC both answered with chain ID 151 (0x97)[4], and returned blocks[4]. The method net_version, which some older tools use to identify a network, returned "method does not exist"[4].

Confirmed

Writing to Redbelly is gated by identity. Every user must claim an access credential from an accredited issuer before their account can write to the network[8], and all participants must prove who they are before gaining access[16]. Accredited issuers are listed in an on-chain registry[17]. Businesses can be verified as incorporated entities[18], and even node operators need network access for their accounts[19].

Confirmed

Receptor is Redbelly's identity and verifiable credential protocol[20], built on the W3C verifiable credential data model[20]. It supports two methods[21]. Proof by Query uses a zero knowledge verifier smart contract[7] and publishes identity state to the chain[7]. Selective Disclosure reveals chosen details to a verifier and can only be used off-chain[22]. The identifiers of Redbelly's accredited credential issuer are specific to Redbelly[23], and apps can use eligibility checks to control who may call their contract functions[24].

Confirmed

Tokeniser runs on Redbelly[6] and enforces eligibility, identity and target market rules at the point of transfer, every time[6]. Before any trade proceeds, identity, eligibility and limits are checked[25]; transfers are recorded on the register in real time[26]; and pledged units stay locked until a loan is repaid[27]. Redbelly settles a transaction in a single round[6].

Confirmed

Redbelly already has token bridges. Its developer portal lists routes through Celer cBridge[28], LayerZero with Stargate[29] and Lucid Labs[30]. Celer uses a pegged bridge method[31]. Redbelly announced Wrapped RBNT on Ethereum with the contract 0xb45f...bf13[32], which the portal lists under Lucid Labs[30]. The portal lists a different Ethereum contract for the Celer route[28].

Confirmed

Community research for TASK-08 found LayerZero live on Redbelly mainnet[33] but no major interoperability protocol on Redbelly testnet[34], and built a lock-and-mint testnet bridge instead[33]. The TASK-16 playbook notes that the official bridges support only some routes[35].

5. Can Redbelly connect now, and what is missing?

A connection can mean three different things. Each has a different answer.

Analysis

Level 1: reaching Redbelly through the Overledger Gateway. Possibly yes, untested.

Redbelly is EVM compatible[3], and Overledger's EVM family covers every EVM compatible chain[2]. An unlisted network in a supported family can be added by the first node registration[2]. Redbelly appears to meet the three self-serve tests: its RPC works over HTTPS[4], reading needs no key[4], and Redbelly's access control applies to accounts, not to which node a client connects to[8]. Ankr, an approved provider[2], runs a Redbelly mainnet endpoint[15], and the official RPC could be added as a private node[2].

Analysis

This level gives an institution one interface to read Redbelly data and send transactions it has signed itself. The Gateway forwards each request unchanged[2], so every Redbelly rule still applies. A transaction sent this way only succeeds if the sending account has Redbelly write access[8].

Unknown

Four points are open. First, the docs do not say which call the EVM health check uses[2]; if it relies on net_version, which Overledger still offers to older tools[5], Redbelly's answer[4] could fail the check. Second, a public node URL must carry a provider API key[2], and we did not confirm that Ankr's keyed service covers Redbelly. Third, the live network list[36] needs an Overledger login[37], so we could not see whether Redbelly is already listed. Fourth, Quant could still decide to treat Redbelly as an engagement network[2].

Analysis

Level 2: Overledger Flow Apps on Redbelly. Unknown.

Flow Apps run signing and other workflows[12]. The catalogue is not published[13] and every shipped app is built by Quant[13], so whether a given app accepts a self-serve EVM network such as Redbelly cannot be checked from public sources. If an app needs extra work for a new chain, the documented effort is about a day per app[2].

Confirmed

Level 3: joining the Fusion Rollup. Not possible yet.

The documented connected networks at testnet launch are Ethereum Sepolia, Polygon Amoy and Quant's permissioned Besu testnet[5]. Each connected chain carries the rollup's bridge and dispute contracts[5] and receives the rollup's state[5]. Token entries on the bridge are controlled by Quant's governance signers[38].

Analysis

The documentation we read describes no self-serve way to add a chain to the Fusion Rollup. On Redbelly, every account that writes needs an access credential[8], so the accounts that deploy those contracts and post rollup state would each need Redbelly network access, and the organisation running them could be verified as a business[18]. This is the main missing piece for Level 3, and only Quant and Redbelly could resolve it.

6. The technical work a connection would need

Written for a non engineer. Steps marked Level 1 are small. Steps marked Level 3 need both Quant and Redbelly to take part, and no such work has been announced[1].

Analysis
  • Level 1, step 1: someone with an Overledger account registers a Redbelly node, either the official RPC as a private node or an approved provider's endpoint as a public node[2]. This is one form or one API call.
  • Level 1, step 2: the node has to pass Overledger's health check[2]. If the check fails on Redbelly, Quant would need to adjust its EVM checker; the documented effort for a full new checker is about 2 days[2].
  • Level 1, step 3: each institution that wants to send transactions needs a Redbelly access credential for every sending address[8], and business verification for the organisation[18]. They can sign with their own keys[13].
  • Level 3, step 1: the rollup's standard bridge and dispute contracts are deployed on Redbelly[5], from accounts that hold Redbelly access[8].
  • Level 3, step 2: the rollup's services start posting rollup state to Redbelly[5].
  • Level 3, step 3: each token that should move is added to the bridge token list by Quant's governance[38].
  • Level 3, step 4: issuers decide whether their asset contracts may hold or release tokens to the bridge contract, because Tokeniser checks eligibility on every transfer[6].
  • Level 3, step 5: someone has to keep Overledger's own allowlists[38] in step with Receptor credentials, because the two systems do not read each other.
Analysis

Registering a node is a technical action any Overledger account can take[2]. It would not by itself mean any agreement between Redbelly and Quant.

7. What a connection could offer institutions

Analysis
  • One interface. An institution that already reaches other chains through Overledger[11] could read Redbelly and send its own signed transactions through the same Gateway, under the same firewall rules[38], without running its own Redbelly integration.
  • Rules stay on Redbelly. At Level 1 the Gateway only forwards requests[2], so Receptor access and Tokeniser eligibility checks still apply to every transaction[6, 8].
  • Key control. Institutions can keep and use their own keys in Overledger's model[13], which matches how a regulated holder would expect to operate.
  • Unified balances, only at Level 3. The Fusion Rollup can merge copies of the same token from several chains into one balance[5]. This is not available to Redbelly today[5].
  • A possible route to tokenised deposit networks. The Clearing House network will use Quant for interoperability[9]. Whether that network will ever reach Redbelly, or any public chain, is unknown[9].
Analysis

Limits to weigh. Redbelly already connects to other chains through Celer, LayerZero and Lucid Labs[28, 29, 30], and Tokeniser points to EVM compatibility as its link to other networks[6]. Overledger would add an institutional access layer rather than a first route out. Level 3 would add another operator to the trust chain, and withdrawals from the rollup wait for a dispute window[5], unlike Redbelly's single round settlement[6].

8. Receptor credentials and Tokeniser assets across chains

Analysis

How Receptor credentials would behave

A Receptor credential is a W3C verifiable credential held by the user[20]. Its two uses travel differently. A Selective Disclosure proof is checked off-chain[22], so in principle any verifier could check it, including an externally hosted Overledger Flow App[12]; none exists today[13]. A Proof by Query check runs in a verifier contract against identity state published on Redbelly[7], so another chain cannot run the same check unless that setup is rebuilt there. The access credential that unlocks write access works only on Redbelly[8].

Analysis

How Tokeniser assets would behave

A Tokeniser asset carries its rules in Redbelly contracts that check every transfer[6, 25]. A bridge moves an asset by locking it on one chain and issuing a copy on the other[33]. The copy obeys only the rules of the contract and policies on the other chain. Overledger's firewall decides access from its own list of users and their addresses[38], not from Receptor credentials.

Analysis

Where compliance could break

  • A copy on another chain without eligibility checks could be passed to someone who never proved eligibility on Redbelly[6].
  • Two lists of who is allowed: Receptor credentials on Redbelly[8] and Overledger's allowlists[38]. If they drift apart, one system allows what the other refuses.
  • A revoked credential on Redbelly[8] does not reach a copy held elsewhere unless someone updates the other list[38].
  • Merged balances[5] could mix a restricted asset with an unrestricted copy of the same asset.
  • The list of tokens that may cross the Fusion bridge is set by Quant's governance[38], not by the issuer.
  • The register is kept on Redbelly in real time[26]. Units held on another chain, or locked in a bridge[27], need clear treatment in that register.
  • Settlement timing changes: rollup withdrawals wait for a dispute window[5], while Redbelly is final in one round[6].
Analysis

The lowest risk pattern is for regulated assets to stay on Redbelly and for Overledger to carry only instructions and data at Level 1, so that every transfer still meets Redbelly's checks[2, 6, 8].

Community summary

Plain language, ready to share. The same text is in COMMUNITY-SUMMARY.md.

Could Redbelly connect to Quant's Overledger? We looked only at public documents. Redbelly and Quant have not announced any partnership or talks, and this research does not suggest any.

Overledger is Quant's platform for reaching many blockchains through one interface. It supports any EVM chain through a self-serve route, and Redbelly is EVM compatible. So a basic connection, reading Redbelly and sending transactions that the sender has signed, looks possible, but nobody has tested it yet. Every Redbelly rule would still apply, including the access credential that every sending account needs.

Overledger's Fusion Rollup, its shared layer for moving tokens between chains, does not include Redbelly, and there is no self-serve way to add a chain. That part is not possible today.

Receptor credentials and Tokeniser's eligibility rules are enforced on Redbelly. They do not travel with a token to another chain. Keeping regulated assets on Redbelly avoids that gap.

Open questions: whether Redbelly passes Overledger's network check, which chains The Clearing House network will reach, and Redbelly's own position on bridging. The full report and every source are linked below.
